# 寒潮低温暴露复核引擎：口径与方法

本目录把室温、室外站点、阀门作业、上门走访、减免回单接入同一套 Node.js 分析，
在降温时重新估计住户低温暴露，并产出能落到具体户时、可回溯到证据键的复核依据。
仅依赖 Node 标准库。入口见 `lib/index.mjs`，命令行见 `tools/cold-review.mjs`。

## 1. 时间与证据时点

- 同一 `period` 内时窗一律按本地时钟的半开区间 `[from, to)` 处理，含起点不含终点；
  小时槽按整点切片，部分小时不允许入账（`lib/time.mjs`）。
- 时段顺序固定为 `H1..H10, A, B, C`，往年样本先于本期冷段 A、巡检段 B、核实段 C。
- 所有分析接受 `asOf` 参数，按“当时可知”截取证据：`known_period` / `recorded_period`
  晚于 `asOf` 的探头登记、测点挪动核实、走访记录都不计入当时结论。
  这样同一事件可以分别复算“当班依据”（`asOf=B`）与“现在可采用证据”（`asOf=C`）。

## 2. 观测成因分类（`lib/observations.mjs`）

每条室温读数按优先级归为互斥一类，四类成因分别保留、不互相冲抵：

| 状态 | 判定 | 暴露处理 |
| --- | --- | --- |
| `low` 真实低温 | 在线、有读数、有人、低于本楼 `low_threshold` | 计入确认低温户时 |
| `ok` 达标 | 在线、有读数、有人、达标 | 触发恢复截止 |
| `unoccupied` 不在家 | `occupied=false` | 不计住户暴露，单独统计 |
| `offline` 离线 | `online=false` | 冷段内进入“未知户时”，不伪造成低温 |
| `missing` 缺测 | 在线但读数为空 | 同上，与离线区分 |

测点挪动通过 `placement-corrections` 解析有效房间：修正只覆盖列出的时窗，
窗口外按 `sensors` 原登记；低温读数若来自挪动测点，单独计数并附放置依据键。

## 3. 冷段识别（`lib/weather.mjs`）

- 各测站用往年 H1–H10 观测的 0.25 分位作为“历史冷阈值”（线性插值分位数）。
  M1 阈值 −4℃、M2 阈值 −6℃，各楼只与**本站对应测站**比较，不跨站套阈值。
- 每个本期读数叠加 `station-error` 的 `lower/upper_delta` 得到真实温度区间：
  区间整体低于阈值判 `cold`，整体高于判 `not_cold`，跨阈值判 `borderline`，
  避免把测站误差二分化。连续冷小时合并为半开时窗。

## 4. 暴露估计与代表性（`lib/exposure.mjs`）

- 统计按**实际住用时长**（有人小时）与楼栋户数估量，户时是基本单位。
- 覆盖率检查同时看本期与往年：有效观测覆盖的独立户数须达到
  `sensor-selection.residence_floor`，且样本不能全部来自投诉户。
  采样设计为 `complaint` 的楼（B1）天然不可向整楼推广。
- 代表性不成立时**不把样本均值推广到整楼**，只输出已确认户时与保守可靠区间，
  并标记 `bookable=false`（仅供复核，不能入账）。
- 可靠区间：
  - 下界 = 已确认低温户时；
  - 上界 = 确认低温 + 冷段离线/缺测未知槽 + 未布点户按观测户平均住用时长的悲观暴露；
  - 代表性楼额外给点估计（观测户住用低温率 × 全楼估计住用小时），点估计必落在区间内。
- 低温持续时间给出去重低温小时槽与最长连续小时数。

## 5. 楼栋间比较（`lib/comparison.mjs`）

- 各楼设定点不同（19/20℃），原始室温不可直接比较，改用**设定点缺口**
  （设定点 − 实测室温）。
- 外气误差敏感性：不同测站的真实温度区间相交时，冷度排序可能被误差反转；
  同测站楼外气条件完全一致，排序天然稳健，不误报。

## 6. 阀门干预归因（`lib/intervention.mjs`）

三级证据，结论附 `actions` 作业键与 `inside` 测点键：

- `intervention_effect`：作业完成、有前后对比，且同热源对照楼无同向变化；
- `contemporaneous`：仅同期关联——同热源楼同量级变化（共同运行暴露），
  或作业时点与寒潮冷段窗口重叠，效果无法分离；
- `undecidable`：作业未完成（`planned`）、缺前后数据或关键测点离线/挪动。
- `walkthrough` 是现场查验而非修复，标 `not_intervention`，不进入效果评估。

本批数据中 H01（B1 换阀）因同热源 B2 同期升温更明显，只能判同期关联；
H02 未完成不可判定；H03 是查验不是干预。

## 7. 核查排程（`lib/scheduling.mjs`）

- 风险分综合确认低温户时、未知范围、代表性缺口与冷段小时，输出优先级。
- 区分三档：需代表性实测（有证据缺口）、仅单元跟进（覆盖达标但有个别低温户）、
  可推迟（无低温无缺口）。片区报告逐楼解释推迟或不可关闭原因。
- 已 `notified`/`proposed` 的上门受保护，新探头预测**不得自动取消**，只能改约；
  同批仪器（同 `device`）时间窗冲突显式暴露并要求改约其一。
- 工单处置：代表性且无冷段缺测可楼栋合并；仅个别户受影响拆回具体单元，
  未覆盖住户保留补交证据通道；证据欠缺则必须补测后才能关闭楼栋工单。
- 住户通知含自身预约单号、时段与原因。

## 8. 减免结算（`lib/rebates.mjs`）

- 基础减免按**单元实测确认低温小时 × 协议单价**，受 `max_hours` 单期封顶，可入账。
- 楼栋估计在非代表性楼标 `review_only`，不得入账、不得冲销单元垫款。
- 防重付：同单元同小时已有 `paid` 垫付的，新回单重叠小时拦截
  （`blocked_duplicate`），换供热主体或追加实测均不解除。
- 恢复截止：单元首次出现达标观测后，其后低温不再计免。
- 已垫付但实测不支撑的回单标 `paid_overclaim_review`，只提示复核，不自动冲销。
- 仅个别户受影响时不得按整楼平均冲销；未覆盖住户可补交证据按单元单独核免。

本批：X1（B1/U1）零支撑超额垫付、X2（B2/U5）足额可入账、
X3（B4/U1）仅 1 小时支撑存在超额。

## 9. 历史处置复核（`lib/evidence.mjs`）

- 证据键 `S*` 解析探头、`I*` 解析上门单；无法定位或跨楼引用直接判证据不成立。
- 迟交的测点挪动/走访按发现时点区分：当时看不到的资料不追溯当班责任，
  但会把当前结论置为 `reassess_with_late_evidence`；证据失效置 `reopen_required`。
- 输出每条处置在 `decided_period` 时点的证据可用性，可回看当班依据了哪批资料；
  并给已关闭处置在后续巡检中的可复用性判断。

本批：K1 因 S1 挪动在 C 期才核实需重估、K2 跨楼引用 S3 需重开、K3 维持。

## 10. 命令

```bash
npm test                          # 53 项规则测试
npm run check:materials           # 交接资料字段与引用校验
npm run report:cold-review        # 全量 JSON 复核报告
node tools/cold-review.mjs exposure   # 单模块报告（cold/exposure/compare/...）
```
